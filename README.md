# AcaRoom · 우리의 아카펠라 연습실

곡을 찾고, 내 파트를 고르고, YouTube로 바로 연습하는 모바일 우선 웹앱입니다. HTML, CSS, Vanilla JavaScript와 JSON만 사용합니다. 별도 서버, 데이터베이스, API 키, npm 설치나 빌드 과정 없이 GitHub Pages에 파일을 올리면 실행할 수 있습니다.

## 1. 프로젝트 소개

홈, 전체 곡, 즐겨찾기, 최근 연습, 설정 화면을 제공합니다. 곡명·아티스트·메모·태그·등록된 파트를 검색하고 상태·장르·난이도·파트 필터를 함께 사용할 수 있습니다. 기본 파트, 즐겨찾기, 최근 연습 10개, 곡/파트별 체크리스트와 진행도를 브라우저에 저장합니다. 연습 화면에는 클릭 후 생성되는 YouTube 플레이어, 원본 영상 열기, 이전/다음 파트, 10분 집중 타이머가 있습니다. 오늘의 랜덤 연습과 라이트·다크·기기 설정 테마도 지원합니다.

현재 `data/songs.json`에는 제공된 Padlet PDF에서 추출한 **실제 29개 곡/편성**과 **공식 YouTube 플레이어 데모 1개**가 있습니다. 보헤미안 랩소디와 디즈니 메들리의 편성별 자료는 별도 항목으로 보존했습니다.

PDF에 직접 포함된 YouTube URL은 2개입니다. **Butterfly ALTO**는 성부가 명확해 실제 연습 버튼에 연결했습니다. 보헤미안 랩소디의 다른 주소는 번호 파트만 확인되고 제목과 설명도 달라 메모와 `source.unknownPartUrls`에 보존했습니다. 나머지 영상 카드에는 Padlet 게시물 주소만 남아 있고 원 게시판은 추출 시 HTTP 403을 반환해 YouTube 주소를 비워 두었습니다. 주소가 없는 곡도 상세 정보를 볼 수 있습니다.

장르·난이도·연습 상태는 **초기 관리값**입니다. 팀의 실제 난이도나 현재 연습 현황을 뜻하지 않으므로 배포 전에 수정하세요. 곡의 `artist`는 PDF에 적힌 공연자·원곡자·편곡 표기를 사용하며 미확인 항목은 비워 두었습니다. 커버는 AcaRoom용으로 만든 추상 SVG이며 실제 앨범 이미지가 아닙니다. 공식 테스트 영상은 아카펠라 음원이 아니라 YouTube API 공식 예제입니다. 앱은 실행 중 Padlet 링크에 접근하지 않습니다.

## 2. GitHub Pages 배포 방법

1. GitHub에 새 저장소를 만들거나 사용할 저장소를 엽니다.
2. 이 프로젝트 폴더 **안의 파일과 폴더**를 저장소에 올립니다. 저장소 루트에 `index.html`, `admin.html`, `404.html`, `css/`, `js/`, `data/`, `assets/`가 보이게 합니다.
3. 저장소의 **Settings → Pages**를 엽니다.
4. **Source: Deploy from a branch**를 선택합니다.
5. **Branch: main**, 폴더 **/(root)**를 선택하고 **Save**를 누릅니다. 다른 기본 브랜치를 쓰면 해당 브랜치를 선택하세요.
6. 배포 완료 후 Pages에 표시된 주소를 엽니다. 프로젝트 저장소라면 보통 `https://username.github.io/repo-name/`입니다.
7. `https://username.github.io/repo-name/admin.html`에서 곡 데이터를 관리할 수 있습니다.

파일 이름은 대소문자까지 그대로 유지하세요. GitHub Pages 배포가 완료되기까지 잠시 걸릴 수 있습니다. 이미 저장소에 다른 사이트가 있다면 해당 사이트와 충돌하지 않는 위치에 배포하세요.

## 3. 로컬에서 안전하게 미리 보는 방법

Python이 설치되어 있다면 터미널에서 프로젝트 폴더로 이동해 다음 명령을 실행합니다.

```bash
cd acaroom
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 엽니다. Windows에서 `python3`가 없다면 `python -m http.server 8000` 또는 `py -m http.server 8000`을 사용할 수 있습니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 이 서버는 로컬 점검용이며 GitHub Pages 배포에는 필요 없습니다.

프로젝트 하위 경로도 확인하려면 `acaroom`의 상위 폴더에서 정적 서버를 실행하고 `http://localhost:8000/acaroom/`에 접속합니다. 코드 편집기의 정적 HTTP 미리보기 기능을 사용해도 됩니다.

## 4. file:// 더블클릭으로 열면 왜 제한되나요?

앱은 `fetch()`로 별도 `data/songs.json`을 읽습니다. `index.html`을 더블클릭하면 브라우저가 `file://` 주소를 사용하고 보안 정책에 따라 로컬 JSON 읽기를 제한합니다. 앱은 이때 “이 앱은 GitHub Pages 또는 HTTP 환경에서 실행해 주세요.”라고 안내합니다.

브라우저 보안을 끄지 말고 위의 HTTP 미리보기 방법을 사용하세요. 정식 실행 기준은 GitHub Pages의 HTTPS 환경입니다. JSON 내용을 HTML이나 JS에 복사할 필요가 없습니다.

## 5. songs.json 구조

파일 위치는 `data/songs.json`입니다. 최상위 객체에 `version: 1`과 `songs` 배열이 있어야 합니다. 다음은 **아직 영상을 등록하지 않은 새 곡의 형식**입니다.

```json
{
  "version": 1,
  "songs": [
    {
      "id": "my-new-song",
      "title": "새 연습곡",
      "artist": "아티스트",
      "category": "K-POP",
      "difficulty": 2,
      "status": "practice",
      "arrangement": "5 Voices",
      "tags": ["공연 준비", "5부"],
      "thumbnail": "",
      "memo": "파트별 링크를 등록해 주세요.",
      "videos": {
        "lead": null,
        "soprano": { "type": "video", "url": "" },
        "alto": { "type": "playlist", "url": "" },
        "tenor": null,
        "baritone": null,
        "bass": null,
        "vp": null,
        "full": { "type": "video", "url": "" }
      }
    }
  ]
}
```

| 항목 | 의미 |
| --- | --- |
| `id` | 비어 있지 않은 고유한 곡 ID. 공유 링크와 개인 기록을 연결합니다. |
| `title` | 필수 곡명. |
| `artist`, `memo`, `arrangement` | 아티스트, 연습 메모, 편성. 모르면 빈 문자열을 사용합니다. |
| `category` | 장르. 데이터에 있는 장르가 필터에 자동으로 추가됩니다. |
| `difficulty` | 숫자 `1` 초급, `2` 중급, `3` 고급. |
| `status` | `practice` 현재 연습, `complete` 완료, `archive` 보관. |
| `tags` | 문자열 배열. |
| `thumbnail` | 빈 문자열, 안전한 HTTP(S) 이미지 URL 또는 `./assets/images/...` 같은 상대경로. |
| `videos` | 파트별 `{ "type": "video" 또는 "playlist", "url": "..." }`, `null`, 빈 객체. |

지원 파트는 `lead` LEAD, `soprano` SOP, `alto` ALTO, `tenor` TENOR, `baritone` BARI, `bass` BASS, `vp` VP, `full` FULL입니다. 빈 URL, `null`, 빈 객체 또는 잘못된 URL은 연습 가능 파트로 표시하지 않습니다.

포함된 데이터의 최상위 `source_note`에는 추출 경위와 초기 관리값의 설명이 있습니다. 곡별 `source`에는 PDF 페이지, 번호 파트, 명시된 성부와 미확인 URL을 보존합니다. 이 부가 필드는 앱의 필수 스키마가 아니며 관리 도구로 편집해도 보존됩니다. 번호만 있는 파트는 성부를 추정해 등록하지 않았습니다.

앱은 중복 ID, 필수값, 난이도, 상태, 미디어 type을 검사합니다. 잘못된 개별 곡은 건너뛰고 개발자 콘솔에 이유를 알리며, 나머지 곡은 계속 표시합니다. JSON 문법 자체가 잘못되면 파일 전체를 읽을 수 없으므로 편집기에서 문법을 확인하세요.

## 6. 새 곡 추가 방법

가장 쉬운 방법은 `admin.html`입니다. **새 곡 추가**를 누르고 ID, 곡명, 분류, 편성을 입력한 뒤 파트별 URL을 등록합니다. **곡 추가**를 눌러 목록에 적용하고 **데이터 검증 → songs.json 다운로드**를 진행합니다. 다운로드한 파일로 GitHub 저장소의 `data/songs.json`을 교체하세요.

직접 편집하려면 `songs` 배열 끝에 위 형식의 곡 객체를 추가합니다. 이전 곡 객체와 새 곡 사이에 쉼표가 필요하고, 마지막 객체 뒤에는 쉼표를 붙이지 않습니다. ID는 `my-new-song`처럼 영문 소문자·숫자·하이픈을 사용하면 공유하기 편합니다. 이미 쓰는 ID와 중복되면 안 됩니다.

## 7. 기존 곡 수정 방법

관리 도구의 곡 목록에서 곡을 선택하고 내용을 수정한 뒤 **변경사항 적용**을 누릅니다. 순서는 위·아래 버튼으로 바꿀 수 있습니다. 삭제 버튼은 관리 도구의 목록에서 곡을 제거하고, 실제 배포 파일은 다운로드한 JSON으로 교체할 때 변경됩니다.

곡명을 바꾸더라도 기존 `id`는 유지하는 것을 권장합니다. ID를 바꾸면 기존 공유 URL과 개인 진행도의 연결이 달라집니다. `status`를 `complete`로 바꾸면 완료 필터에, `practice`로 바꾸면 홈의 현재 연습곡에 표시됩니다. 체크리스트 완료는 개인 기록이므로 데이터의 곡 상태를 자동 변경하지 않습니다.

## 8. 파트별 YouTube URL 입력법

원본 영상을 열고 공유 URL을 복사해 해당 성부의 URL 칸에 붙여 넣습니다. 다음 형식을 지원합니다.

```text
https://www.youtube.com/watch?v=VIDEO_ID
https://youtu.be/VIDEO_ID
https://www.youtube.com/embed/VIDEO_ID
https://www.youtube.com/shorts/VIDEO_ID
https://www.youtube.com/playlist?list=PLAYLIST_ID
https://www.youtube.com/watch?v=VIDEO_ID&list=PLAYLIST_ID
```

`m.youtube.com`, `music.youtube.com` 주소도 지원합니다. 위 `VIDEO_ID`, `PLAYLIST_ID`는 설명용 자리표시자이므로 실제 URL을 붙여 넣으세요. YouTube 이외의 주소나 잘못된 ID는 오류로 안내합니다. 등록할 자료가 없다면 URL을 비워 두세요. 번호 파트만 있는 원본 자료는 실제 SOP·ALTO 등의 성부를 확인한 뒤 등록하세요.

## 9. video와 playlist 차이

`video`는 영상 한 편을 재생합니다. URL에 `v`와 `list`가 둘 다 있어도 영상 ID를 우선 사용합니다. `playlist`는 재생목록을 재생하고 `list`를 우선 사용합니다. 단일 영상 URL을 넣고 `playlist`로 선택하면 재생목록 ID가 없어 검증 오류가 납니다.

임베드는 가능한 한 `youtube-nocookie.com` 주소를 사용합니다. 모든 영상이 임베드를 허용하는 것은 아니므로 연습 화면의 **YouTube에서 열기**를 사용하면 원본 주소로 이동할 수 있습니다. 카드에는 iframe을 넣지 않고 사용자가 재생을 눌렀을 때만 생성합니다.

공식 테스트 영상의 출처는 [YouTube IFrame Player API 문서](https://developers.google.com/youtube/iframe_api_reference)입니다. 앱 데이터에는 임의의 재생목록을 넣지 않았고 재생목록 URL 형식은 개발용 검증 자료로 확인합니다.

## 10. admin.html 사용법

1. 앱의 설정에서 데이터 편집기를 열거나 배포 주소 뒤에 `admin.html`을 붙입니다.
2. 현재 `data/songs.json` 불러오기가 자동으로 시도됩니다. 필요하면 **현재 songs.json 불러오기**를 누르거나 **JSON 파일 가져오기**로 로컬 파일을 선택합니다.
3. 곡을 선택해 수정하거나 새 곡을 추가합니다. 파트별 영상/재생목록 종류와 URL을 따로 입력합니다. 태그는 쉼표로 구분합니다.
4. 입력한 내용을 **곡 추가/변경사항 적용**으로 목록에 반영합니다.
5. **데이터 검증**으로 중복 ID, 필수값, 난이도·상태·type, YouTube URL을 확인합니다. 빈 URL은 오류가 아닙니다.
6. **JSON 미리보기**로 결과를 확인하고 **songs.json 다운로드**를 누릅니다.
7. 다운로드한 파일을 저장소의 `data/songs.json`과 교체하고 변경사항을 커밋합니다. GitHub Pages 배포가 완료되면 앱을 새로고침합니다.

관리 도구는 GitHub 자동 업로드나 서버 저장을 하지 않습니다. 다운로드 전 편집 내용은 해당 페이지에만 남아 있으므로 페이지를 닫기 전에 파일을 보관하세요. `admin.html`은 로그인 화면이 아니지만 방문자가 서버의 원본 JSON을 수정할 수는 없습니다. 저장소 수정 권한을 가진 사람이 다운로드 파일을 올려야 배포 내용이 바뀝니다.

## 11. Padlet 자료를 JSON으로 옮기는 방법

Padlet 게시물을 직접 열어 곡명과 편성을 정리합니다. 미디어 카드의 실제 YouTube 링크를 복사하고, 성부 이름을 확인해 관리 도구의 해당 파트에 등록합니다. 참고 공연이나 전체 믹스는 `full`로 등록하되 실제 곡과 일치하는지 확인하세요.

PDF export에는 미디어 카드의 YouTube URL 대신 Padlet 게시물 링크만 남을 수 있습니다. PDF의 `YouTube` 글자가 보인다고 해서 영상 ID를 추측하지 마세요. 원본 게시물에서 주소를 확보할 수 없다면 URL을 비워 두고 메모에 원본 위치를 적습니다. 현재 데이터의 `source.pages`와 `numberedParts`를 참고하면 빠진 자료를 찾기 쉽습니다.

번호 파트 주소는 성부를 확인한 후 `videos`에 옮깁니다. 보헤미안 랩소디의 미확인 주소는 곡 메모와 `source.unknownPartUrls`에 있습니다. 임시 PDF export 링크가 만료되어도 JSON을 저장한 이후 앱 실행에는 영향을 주지 않습니다. 실제 자료를 등록한 후 공식 테스트 데모 항목은 삭제해도 됩니다.

## 12. localStorage 저장 항목

| 키 | 저장 내용 |
| --- | --- |
| `acaroom:v1:favorites` | 즐겨찾기 곡 ID. |
| `acaroom:v1:recent` | 최근 연습의 `songId`, `part`, `timestamp`, 최대 10개. 같은 곡/파트는 최신 위치로 이동합니다. |
| `acaroom:v1:myPart` | 기본 파트. |
| `acaroom:v1:progress` | 곡 ID → 파트 → 체크리스트 항목별 참/거짓. |
| `acaroom:v1:theme` | 기기 설정/라이트/다크 테마. |
| `acaroom:v1:timer` | 집중 타이머의 실행 상태, 남은 시간, 종료 시각. |

개인 기록은 현재 브라우저에만 저장되고 다른 기기와 자동 동기화되지 않습니다. 홈에서는 최근 5개, 최근 연습 화면에서는 최대 10개를 표시합니다. 데이터에서 삭제된 곡 기록은 안전하게 무시합니다. 브라우저 저장소가 차단되거나 가득 차면 앱은 현재 세션의 메모리로 계속 동작하지만 새로고침 후 기록이 유지되지 않을 수 있습니다.

타이머는 실제 종료 시각을 기준으로 남은 시간을 계산합니다. 다른 앱으로 이동하거나 브라우저 탭이 느려져도 돌아오면 실제 경과 시간을 반영합니다. 기기의 시계를 수동으로 바꾸면 계산에 영향을 줄 수 있습니다. 설정의 **개인 연습 기록 초기화**는 즐겨찾기·최근 연습·진행도·타이머를 지우고 기본 파트와 테마는 유지합니다.

## 13. 자주 발생하는 오류와 해결 방법

| 상황 | 해결 방법 |
| --- | --- |
| “GitHub Pages 또는 HTTP 환경에서 실행” 안내 | 파일 더블클릭 대신 로컬 HTTP 서버 또는 GitHub Pages 주소를 사용합니다. |
| 곡 데이터를 불러오지 못함 | `data/songs.json`이 배포되었는지, 파일 이름 대소문자와 JSON 문법이 맞는지 확인한 뒤 다시 시도합니다. |
| 곡 일부가 목록에서 빠짐 | 개발자 콘솔의 `[AcaRoom]` 경고와 관리 도구의 데이터 검증 결과를 확인합니다. 중복 ID나 잘못된 필수값은 수정하세요. |
| 연습 가능한 파트가 없음 | URL이 비어 있거나 형식이 잘못되었을 수 있습니다. 원본 YouTube 주소와 미디어 종류를 등록하세요. |
| YouTube 재생이 차단됨 | **YouTube에서 열기**로 원본에서 재생하세요. 게시자의 임베드 제한, 영상 삭제, 지역/연령 제한은 앱이 해제할 수 없습니다. |
| 썸네일이 기본 커버로 보임 | 이미지가 없거나 주소가 잘못된 경우입니다. `thumbnail`의 경로를 확인하세요. 앱은 로고 기반 커버를 대신 표시합니다. |
| 검색 결과가 없음 | 검색어를 지우거나 필터 초기화를 누릅니다. 장르 필터는 등록된 데이터에서 가져옵니다. 파트 필터는 실제 영상 주소가 있는 곡만 찾습니다. |
| 개인 기록이 사라짐 | 같은 브라우저·배포 주소를 쓰는지, 사이트 데이터가 삭제되거나 저장소가 차단되었는지 확인합니다. |
| 공유가 동작하지 않음 | Web Share API가 없으면 복사를 시도하고, 복사도 제한되면 선택 가능한 URL 입력창을 표시합니다. 주소를 직접 복사하세요. |
| 공유한 곡/파트를 찾을 수 없음 | 곡 ID와 등록된 파트를 확인합니다. 없는 곡은 홈으로, 없는 파트는 곡 상세로 돌아갑니다. |
| Padlet 접근 실패 | 원본 자료를 수동으로 확인할 때만 필요합니다. 앱은 로컬 JSON으로 계속 실행됩니다. |
| 관리 도구의 편집이 앱에 반영되지 않음 | JSON을 다운로드한 뒤 GitHub의 `data/songs.json`을 교체하고 Pages 재배포 완료 후 새로고침하세요. |

빈 `songs` 배열도 오류 없이 빈 상태로 표시합니다. 곡명·메모·태그는 텍스트로 렌더링하며 JSON에 HTML을 넣어도 실행하지 않습니다.

## 14. GitHub Pages 프로젝트 경로 주의사항

CSS, JavaScript, JSON, 아이콘과 이미지 경로는 상대경로입니다. `/css/style.css`처럼 도메인 루트에서 시작하는 자원 경로로 바꾸지 마세요. 새 썸네일은 `./assets/images/my-cover.svg`처럼 앱의 HTML 위치를 기준으로 입력합니다. 데이터가 `data/` 안에 있어도 썸네일 경로를 `../assets/...`로 적을 필요는 없습니다.

공유 링크는 `index.html?song=butterfly`, `index.html?song=butterfly&part=alto`처럼 query string을 사용합니다. `/song/butterfly` 같은 가상 경로는 사용하지 않습니다. 브라우저 뒤로/앞으로 이동도 query 상태로 복원합니다.

`404.html`은 오류 안내와 홈 링크만 표시하며 자동 리다이렉트를 하지 않습니다. 깊은 잘못된 URL에서도 상위 폴더의 AcaRaca 로고를 확인해 홈 링크를 배포 루트로 맞춥니다. JavaScript나 네트워크가 꺼져 있으면 저장소의 기본 Pages 주소로 돌아가세요.

PWA와 Service Worker는 포함하지 않습니다. 파일 수정은 일반 GitHub Pages 배포로 반영되며 YouTube 영상이나 iframe을 오프라인 캐시하지 않습니다.

## 15. 구현 검수 기록

Chromium 브라우저에서 검색·복합 필터, 즐겨찾기·내 파트·진행도 저장, 최근 기록 제한과 중복 제거, 직접 공유 URL, 뒤로/앞으로 이동, 공유 복사 실패 안내, 영상 지연 생성, 잘못된 데이터 처리 등 **27개 기능 시나리오**를 확인했습니다. URL 파서·데이터·검색·저장소·플레이어 자체 검사는 브라우저 기준 **59개 통과**입니다.

360×800, 390×844, 768×1024, 1366×768에서 가로 넘침과 JavaScript 실행 오류를 점검했고, 집중 타이머의 시작·일시정지·재개·새로고침 복원·종료와 영상의 16:9 비율을 확인했습니다. 관리자 편집기의 추가·수정·삭제·순서 변경·가져오기·다운로드도 검수했습니다. 프로젝트 하위 경로에서 실제 JSON과 CSS·JS·이미지가 정상 로딩됩니다.

실제 30개 항목을 넣고 네 가지 화면 크기에서 홈·목록·상세·연습·설정·편집기를 확인했습니다. 자동 접근성 검사에서는 라이트·다크 화면 9곳에서 위반 사항이 보고되지 않았습니다. 일부 이미지 위 텍스트와 브라우저 기본 컨트롤은 도구의 자동 판단 범위에 제한이 있습니다.

개발용 자체 검사를 다시 실행하려면 HTTP로 앱을 연 뒤 개발자 도구 콘솔에서 다음을 입력하세요. 별도 테스트 프레임워크나 빌드는 필요하지 않습니다.

```js
(await import('./tests/core-tests.js')).runCoreTests()
```

재생목록 ID는 파서 검사에만 사용하는 가상 입력입니다. 실제 라이브러리에는 확인되지 않은 영상·재생목록 주소를 넣지 않았습니다. GitHub 저장소로의 업로드와 실제 Pages 배포는 위의 배포 절차에 따라 진행하세요.
